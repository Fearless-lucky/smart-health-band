## 第4章 传感器驱动是怎么写的

以 MAX30102（心率血氧传感器）为例，逐层讲解驱动代码的编写思路。

### 4.1 驱动代码的三层结构

每个传感器驱动都遵循同样的三层模式：

```
┌────────────────────────────────────┐
│  API 层  (max30102.h)              │  ← 对外：Init() + ReadData()
├────────────────────────────────────┤
│  逻辑层  (max30102.c 公开函数)     │  ← 寄存器配置、数据读取、错误处理
├────────────────────────────────────┤
│  物理层  (static 函数)             │  ← write_reg/read_reg：真正操作 I2C
└────────────────────────────────────┘
```

**为什么分三层？** 如果换个单片机（比如从 STM32F103 换成 STM32F407），只需要改物理层的 I2C 操作函数，API 层和逻辑层完全不用动。这就是硬件抽象的思想。

### 4.2 初始化函数逐行讲解

```c
int MAX30102_Init(void)
{
    /* ① 软件复位 — 相当于"重启路由器" */
    write_reg(REG_MODE_CONFIG, 0x40);
    // REG_MODE_CONFIG 是寄存器 0x09
    // 0x40 = 0100 0000 = 第6位 RESET=1，芯片内部复位
    Delay_ms(10);   // 等芯片重启完成

    /* ② 关闭所有中断 — 本项目用轮询，不用中断 */
    write_reg(REG_INTR_ENABLE_1, 0x00);
    write_reg(REG_INTR_ENABLE_2, 0x00);
    // 如果开中断，MAX30102 FIFO 满了会拉低 INT 引脚
    // 但我们选择每 200ms 主动查询，简单可靠

    /* ③ 配置 FIFO — 数据缓冲区 */
    write_reg(REG_FIFO_CONFIG, 0x10);
    // 0x10 = 0001 0000
    // 第4位=1: FIFO 满了之后滚动覆盖（新的覆盖旧的）
    // 第[3:0]=0: 不平均（每个样本单独存储）

    /* ④ 清空 FIFO 读写指针 */
    write_reg(REG_FIFO_WR_PTR, 0x00);  // 写指针归零
    write_reg(REG_FIFO_RD_PTR, 0x00);  // 读指针归零
    write_reg(REG_OVF_COUNTER, 0x00);  // 溢出计数器归零
    // 这就像把水桶倒空——初始化时桶里不应有旧数据

    /* ⑤ 退出复位 — 芯片正式进入工作模式 */
    write_reg(REG_MODE_CONFIG, 0x00);
    Delay_ms(10);

    /* ⑥ 配置 SPO2 模式 — 决定采样率和 ADC 精度 */
    write_reg(REG_SPO2_CONFIG, 0x47);
    // 0x47 = 0100 0111
    // [6:5]=01: ADC 量程 4096 (16-bit 不够，取高 18-bit)
    // [4:2]=001: 采样率 100Hz (每秒采 100 个样本)
    // [1:0]=11: 脉冲宽度 411μs (LED 点亮时间，越宽信号越强但功耗越大)

    /* ⑦ 设置 LED 电流 — 控制发光强度 */
    write_reg(REG_LED1_PA, 0x50);   // IR (红外) LED: 0x50 ≈ 16mA
    write_reg(REG_LED2_PA, 0x50);   // Red (红光) LED: 0x50 ≈ 16mA
    // 0.2mA/step × 0x50(80) = 16mA
    // 电流越大，信号越强，但功耗越大，手指也越热

    /* ⑧ 进入 SpO2 双 LED 模式 */
    write_reg(REG_MODE_CONFIG, 0x03);
    // 0x03 = 0000 0011
    // [2:0]=011: SpO2 模式 (IR + Red 交替亮灯)
    // 其他模式: 000=关闭, 001=心率模式(仅IR), 010=SpO2(仅Red)
    Delay_ms(50);

    return 0;
}
```

**寄存器是什么？** 把芯片想象成一栋大楼，寄存器就是一个个房间。0x09 号房间是"模式控制"，0x0A 号房间是"SPO2 配置"。往房间里面写不同的数字，芯片就会做不同的事情。

### 4.3 数据读取函数逐行讲解

```c
int MAX30102_ReadData(int32_t *ir, int32_t *red, uint16_t *count)
{
    if (!count) return -2;          // 防御：count 指针不能为空
    uint16_t capacity = *count;     // 调用方最多能接收多少样本
    *count = 0;                     // 先清零输出计数

    /* ① 读 FIFO 读写指针 — 知道有多少新数据 */
    uint8_t wr = read_reg(REG_FIFO_WR_PTR);  // 写指针：芯片写到哪了
    uint8_t rd = read_reg(REG_FIFO_RD_PTR);  // 读指针：程序读到哪了

    /* ② 计算新样本数 */
    int samples = (int)((wr - rd) & 0x1F);
    // FIFO 只有 32 个槽位 (0-31)，用 & 0x1F 处理环形计数回绕
    // 写指针=10, 读指针=5 → samples=5 (有5个新样本)
    // 写指针=3, 读指针=28 → (3-28)&0x1F = (-25)&0x1F = 7 (环形：28→31→0→3)
    if (samples <= 0) return -1;    // 无新数据
    if (samples > 32) samples = 32; // 安全裁剪

    /* ③ 一次性读取全部新样本 */
    uint8_t raw[192];               // 最多 32 样本 × 6 字节/样本 = 192
    int to_read = samples * 6;
    I2C_ReadReg(MAX30102_I2C_ADDR, REG_FIFO_DATA, raw, to_read);
    // FIFO 数据寄存器 0x07 支持连续读取——每次读后指针自动+1

    /* ④ 解码：把 3 字节拼成 18-bit 数值 */
    int32_t ir_dec[32], red_dec[32];
    for (int i = 0; i < samples; i++) {
        int idx = i * 6;
        // 每 6 字节 = 1 个样本：Red[0:2] + IR[3:5]，每个值占 3 字节(高18位有效)
        int32_t r = ((int32_t)raw[idx] << 16)
                  | ((int32_t)raw[idx + 1] << 8)
                  | raw[idx + 2];
        int32_t ri = ((int32_t)raw[idx + 3] << 16)
                   | ((int32_t)raw[idx + 4] << 8)
                   | raw[idx + 5];
        red_dec[i] = r  & 0x3FFFF;  // 只保留低 18 位 (3FFFF = 262143)
        ir_dec[i]  = ri & 0x3FFFF;
    }

    /* ⑤ 输出给调用方 */
    int out_n = (samples < (int)capacity) ? samples : (int)capacity;
    for (int i = 0; i < out_n; i++) {
        if (ir)  ir[i]  = ir_dec[i];   // 传 NULL 表示调用方不需要这些数据
        if (red) red[i] = red_dec[i];
    }
    *count = (uint16_t)out_n;

    /* ⑥ 送入算法层处理 */
    PPG_ProcessSamples(ir_dec, red_dec, (uint16_t)samples);
    // 全部样本都送给算法，不限于调用方请求的数量
    return 0;
}
```

**FIFO 是什么？** 想象一个旋转寿司传送带，上面有 32 个盘子。芯片（厨师）不断往空盘子上放寿司，程序（食客）从传送带上取。如果食客太慢，新寿司就会覆盖旧寿司（滚动覆盖模式）。这就是为什么 Sensors 任务优先级最高——不能让寿司被覆盖。

## 第5章 从红光波形到心率数字：PPG 信号处理

这是整个项目最核心、也最复杂的算法部分。我们从物理原理讲到代码实现。

### 5.1 心率和血氧是怎么测出来的？

**光电容积描记术（PPG）的基本原理**：

```
      LED发光
         │
    ┌────▼────┐
    │  手指   │  ← 血管随心跳扩张/收缩
    └────┬────┘
         │
    ┌────▼────┐
    │ 光电二极管 │  ← 接收透过的光
    └─────────┘
```

心跳一次 → 血管扩张 → 更多血液 → 吸收更多光 → 光电二极管收到的光变少 → 电信号出现一个"谷"
心跳间歇 → 血管收缩 → 更少血液 → 吸收更少光 → 光电二极管收到的光变多 → 电信号出现一个"峰"

所以 PPG 信号是一个**随心跳波动的波形**。信号的交流分量（AC）来自脉搏血流量变化，直流分量（DC）来自组织、骨骼、皮肤等固定结构。

**为什么用两种光（红外 + 红光）？**

含氧血红蛋白（HbO2）和脱氧血红蛋白（Hb）对红外光和红光的吸收率不同：
- HbO2 吸收更多红外光 → 红外光的 AC/DC 比值反映氧合程度
- Hb 吸收更多红光 → 红光的 AC/DC 比值反映脱氧程度

通过比较两种光的 AC/DC 比值，就能算出 SpO2。

### 5.2 信号处理管线

原始数据要经过以下处理步骤：

```
MAX30102 FIFO
     │
     ▼
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  去直流   │ → │  低通滤波 │ → │  峰值检测 │ → │  EMA平滑 │ → 心率 BPM
│ (HP 0.5Hz)│    │ (LP 5Hz) │    │          │    │ (α=0.15) │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                     │
                                     ▼
                               ┌──────────┐
                               │ 算 R 值  │ → SpO2 %
                               └──────────┘
```

### 5.3 带通滤波：为什么要滤？怎么滤？

原始信号中有三种成分：

```
原始信号 = 直流(DC) + 脉搏波(0.5-5Hz) + 噪声(运动伪影/50Hz工频干扰)
            ↑ 没用的    ↑ 我们要的！        ↑ 干扰
```

**高通滤波器（HP, 0.5Hz）— "去直流"**：去掉不变的直流成分（骨骼、组织的固定吸收），只保留变化的信号。

**低通滤波器（LP, 5Hz）— "去毛刺"**：去掉高频噪声（电路噪声、微小的手抖），让波形变平滑。

```
原始波形:  /\/\/\/\/\/\/\/\/\/\/  (带毛刺)
高通后:    ~^~^~^~^~^~^~^~^~^~^  (去掉了缓慢漂移的直流)
低通后:    ~~~~~~~~^^^^^^^^~~~~~~  (平滑的脉搏波形！)
```

**代码实现：一阶 IIR 滤波器**

```c
// PPG_Init() 中计算滤波系数
float rc_lp = 1.0f / (2.0f * 3.1415926535f * 5.0f);  // LP 截止频率 5Hz
float rc_hp = 1.0f / (2.0f * 3.1415926535f * 0.5f);  // HP 截止频率 0.5Hz
float dt    = 1.0f / 100.0f;                          // 采样间隔 (100Hz)
alpha_lp = dt / (rc_lp + dt);   // 低通平滑系数
alpha_hp = dt / (rc_hp + dt);   // 高通平滑系数

// PPG_ProcessSamples() 中的滤波循环
for (uint16_t j = 0; j < N; j++) {
    float x   = window_ir[j];                      // 当前输入样本
    float yhp = alpha_hp * (prev_hp + x - prev_x); // 高通: 输出 = α×(上次输出 + 输入变化量)
    prev_hp   = yhp;
    float ylp = prev_lp + alpha_lp * (yhp - prev_lp); // 低通: 输出 = 上次输出 + α×(高通输出 - 上次输出)
    prev_lp   = ylp;
    prev_x    = x;
    filtered[j] = ylp;   // 最终结果
}
```

**直观理解**：`alpha` 越小，滤波越"重"（越平滑但越迟钝）。每次只取一点点新值来修正旧值，就像慢慢调节水温而不是猛地开大水龙头。

### 5.4 动态阈值峰值检测：怎么找到心跳

滤波后的波形是一串波动的数字。怎么判断"这里是一个心跳"？

```c
float mean = calc_mean(filtered, N);    // 计算平均值
float stdv = calc_std(filtered, N, mean); // 计算标准差（波动程度）
float thresh = mean + 0.8f * stdv;      // 阈值 = 均值 + 0.8 × 标准差

for (uint16_t i = 1; i < N - 1; i++) {
    if (filtered[i] > thresh &&           // ① 高于阈值
        filtered[i] > filtered[i - 1] &&  // ② 比左边高
        filtered[i] > filtered[i + 1]) {  // ③ 比右边高
        // ↑ 三个条件同时满足 → 这是一个峰值！
        add_peak(abs_idx);
    }
}
```

**为什么阈值是 `mean + 0.8 × 标准差` 而不是固定值？**

因为每个人的手指厚度、肤色、按压力度不同，导致信号幅度差异很大。用动态阈值（基于当前信号统计量）能适应不同人的手指。

```
信号幅度大的人: mean=10000, std=2000 → threshold = 10000 + 1600 = 11600
信号幅度小的人: mean=5000,  std=800  → threshold = 5000 + 640 = 5640
```

### 5.5 从峰值间距算出心率

```c
// 取最近的 8 个峰值（或全部），计算平均间距
uint32_t n = (peak_count - 1 > 8) ? 8 : (peak_count - 1);
for (uint32_t k = start; k < start + n; k++) {
    sum_period += (peak_times[k+1] - peak_times[k]) / 100.0;  // 间距(秒)
}
double avg_period = sum_period / n;  // 平均间距

// 合理性检查
if (avg_period < 0.3 || avg_period > 2.0) return 0;
// 0.3秒 = 200bpm (太快，不是心跳)
// 2.0秒 = 30bpm  (太慢，也不是心跳)

// 计算心率
return (int)(60.0 / avg_period + 0.5);
// 60/0.8秒 = 75 bpm ← 正常人静息心率
```

### 5.6 EMA 平滑：让数字不再"跳"

如果直接显示 `compute_hr()` 的结果，数字会在 70→75→72→78→71 之间乱跳（因为噪声导致个别峰值偏移）。用指数移动平均（Exponential Moving Average）让变化更平滑：

```c
ema_hr = 0.15f * (float)new_hr + 0.85f * ema_hr;
hr = (int)(ema_hr + 0.5f);
```

**类比**：你往一杯咖啡里加牛奶——新心率是纯牛奶（15%），旧心率是咖啡（85%）。搅匀后的颜色缓慢变化，而不是突然变白。α=0.15 意味着每次只接受 15% 的新信息。

### 5.7 血氧 SpO2 计算

```c
// 计算 R 值 = (AC_red/DC_red) / (AC_ir/DC_ir)
// AC ≈ 标准差(代表波动幅度)
// DC ≈ 平均值(代表基线)
float R = (std_red / mean_red) / (std_ir / mean_ir);

// 校准公式：SpO2 = A - B × R
int est = (int)(110.0f - 25.0f * R + 0.5f);

// 安全裁剪
if (est < 50)  est = 50;   // 低于50%不合理
if (est > 100) est = 100;  // 高于100%不可能

// 同样用 EMA 平滑
ema_spo2 = 0.15f * (float)est + 0.85f * ema_spo2;
spo2 = (int)(ema_spo2 + 0.5f);
```

**CAL 命令的作用**：不同硬件、不同环境光条件下，A=110、B=25 的默认值可能不准。用户可以通过蓝牙发送 `CAL 115 28` 来微调校准参数。

**信号质量判定**：当标准差 < 0.2（手指没放上去或完全没信号）时，算法把心率和血氧都归零——"没信号时不乱报"。
