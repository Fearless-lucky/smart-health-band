## 一、工程总览

### 1.1 项目定位

这是一款基于 **STM32F103ZE + FreeRTOS** 的智能健康手环固件，集成五项健康监测能力：

| 功能 | 传感器 | 通信总线 | 输出 |
|------|--------|---------|------|
| 心率 (HR) | MAX30102 (PPG 光电) | I2C1 (0x57) | bpm |
| 血氧 (SpO2) | MAX30102 | I2C1 (0x57) | % |
| 计步 / 运动识别 | MPU6050 (六轴) | I2C1 (0x68) | 步数 + 状态 |
| 体温 | DS18B20 (1-Wire) | PA0 单总线 | °C（含环境补偿）|
| 实时时钟 | DS1302 | PB1/PB12/PB9 三线 | HH:MM:SS |
| 显示 | SSD1306 OLED 128×64 | I2C2 (0x3C) | 5 页面轮转 |
| 无线上报 | HC-05 蓝牙 | UART1 (PA9/PA10) | JSON @2s |
| 语音控制 | ASR PRO | UART2 (PA2/PA3) | 9 条单字节命令 |

### 1.2 技术栈

- **MCU**：STM32F103ZE（Cortex-M3，72MHz，512KB Flash / 64KB SRAM，144 脚 LQFP，大容量 HD 系列）
- **RTOS**：FreeRTOS（本地源码 `freertos/`，heap_4 内存管理，CM3 端口）
- **外设库**：STM32 标准外设库 StdPeriph_Driver（非 HAL/LL，老牌库）
- **工具链**：Keil MDK（`TASK1.uvprojx`），启动文件 `startup_stm32f10x_hd.s`
- **构建产物**：Flash 镜像在 `Objects/`，反汇编/列表在 `Listings/`

### 1.3 关键资源预算

| 资源 | 占用 | 来源 |
|------|------|------|
| FreeRTOS 堆 | 15 KB | `FreeRTOSConfig.h: configTOTAL_HEAP_SIZE` |
| 任务栈合计 | 7.25 KB | (512+512+384+384) words × 4 + 定时器任务 256 words |
| OLED framebuffer | 1 KB | `oled_ssd1306.c: framebuf[8][128]` |
| PPG 信号缓冲 | 2 KB | `algorithms.c: ppg_ir[256] + ppg_red[256]` (float×2) |
| Tick 频率 | 1000 Hz | `configTICK_RATE_HZ`（1ms 粒度）|
| 抢占优先级 | 5 级 | `configMAX_PRIORITIES`（任务用 2、3 级）|

## 二、系统架构与数据流

### 2.1 分层架构

```
┌─────────────────────────────────────────────────────┐
│  应用层  main.c — 4 个 FreeRTOS 任务 + 初始化流程      │
├──────────────┬───────────────┬──────────────────────┤
│  交互层      │  算法层        │  传感器/外设驱动层     │
│ oled_ssd1306 │ algorithms    │ max30102  mpu6050    │
│ keys         │ (PPG/Step/    │ ds18b20   ds1302     │
│ hc05         │  SpO2/Temp/   │                       │
│ asr_pro      │  Activity)    │                       │
├──────────────┴───────────────┴──────────────────────┤
│  HAL 层   i2c_hal (I2C1+I2C2)  uart_hal (UART1+2)   │
│           systick (DWT 精确定时)                      │
├─────────────────────────────────────────────────────┤
│  厂商层   StdPeriph_Driver + CMSIS + FreeRTOS 内核   │
└─────────────────────────────────────────────────────┘
```

### 2.2 FreeRTOS 任务模型

4 个任务均为**周期性轮询**（无中断驱动，全软件轮询），由 `vTaskDelay` 控制周期：

| 任务 | 优先级 | 周期 | 栈(words) | 职责 | 数据产出 |
|------|:---:|:---:|:---:|------|------|
| `Sensors` | **3** (最高) | 200ms | 512 | 读 MAX30102 FIFO → PPG；读 MPU6050 → 计步；每 4 周期读 DS18B20 → 体温 | hr, spo2, steps, g_temperature |
| `Display` | 2 | 50ms | 512 | OLED 5 页面刷新 + 按键翻页 | 像素 |
| `Voice` | 2 | 100ms | 384 | 解析 ASR PRO UART2 命令 | OLED 内容 / g_page_advance |
| `BT` | 2 | 20ms | 384 | HC-05 命令解析 + 2s JSON 上报 | 蓝牙 TX |

**设计要点**：Sensors 优先级最高，保证健康数据采样实时性（MAX30102 100Hz 采样，200ms 读一次约累积 20 样本，FIFO 容量 32 有 60% 余量）。其余 3 任务同级，按就绪顺序调度。

### 2.3 数据流图

```
                  ┌──────────────────────────────────────────┐
                  │            Sensors 任务 (200ms)           │
                  │ MAX30102 FIFO ──► PPG_ProcessSamples      │
                  │ MPU6050 ────────► Step_ProcessAccel       │
                  │ DS18B20 ────────► Compensate_Temperature  │
                  └──────────┬───────────────────────────────┘
                             │ 写 volatile 全局
              ┌──────────────┼──────────────┬─────────────┐
              ▼              ▼              ▼             ▼
          hr/spo2        steps      g_temperature     activity_state
        (static int)  (static int) (volatile float)  (static enum)
              │              │              │             │
   ┌──────────┴──────┐ ┌─────┴──────┐ ┌─────┴─────┐       │
   │  Display 任务   │ │ BT 任务    │ │           │       │
   │ OLED 5 页面刷新 │ │ 2s JSON上报│ │           │       │
   │ ◄── 按键 PE3/4  │ │ ◄── AT/TIME│ │           │       │
   │ ◄── g_page_adv  │ │   /CAL 命令│ │           │       │
   └─────────────────┘ └────────────┘ │           │       │
                                      ▼           ▼       ▼
   ┌──────────────────────────────────────────────────────────┐
   │              Voice 任务 (100ms) — ASR PRO UART2          │
   │   0x01~0x09 命令 → OLED 直接绘制 / 置 g_page_advance      │

```

### 2.4 跨任务共享数据与同步策略

| 数据 | 类型 | 写者 | 读者 | 同步方式 |
|------|------|------|------|---------|
| `hr` / `spo2` / `steps` | `volatile int` | Sensors | Display/BT | 无锁（M3 上 32 位读原子）|
| `g_temperature` | `volatile float` | Sensors | Display/BT | **临界区取快照**（防 float 撕裂）|
| `g_temp_valid` | `volatile int` | Sensors | Display/BT | 临界区（与 temperature 一起取）|
| `g_page_advance` | `volatile int` | Voice/ASR | Display | 无锁（标志位）|
| `steps` 自增 | int | Sensors (Step) | — | **临界区**（被 Reset 跨任务改）|
| OLED framebuffer | `uint8_t[8][128]` | Display + Voice | — | **无锁**（潜在竞争，见评审）|
| I2C1 总线 | — | Sensors | — | **互斥锁**（MAX30102+MPU6050 共享）|

## 三、分层详解

### 3.1 HAL 底层通信层

#### 3.1.1 `systick.c` — DWT 硬件周期计数精确定时

**目的**：为 1-Wire（DS18B20）和三线（DS1302）这类**时序敏感**的软件模拟协议提供微秒级精确延时，传统 SysTick 重载难以满足。

**原理**：
- `Systick_Init()` 使能 CoreDebug 的 `TRCENA` 和 DWT 的 `CYCCNT`（数据观察点跟踪单元的周期计数器，每个 CPU 时钟 +1）
- `Delay_us()` 用 `DWT->CYCCNT` 差值实现：`target = us × (72MHz/1e6)`。**无符号减法天然处理 32 位回绕**（`CYCCNT - start` 在回绕后仍正确，因 uint 取模性质）
- `Systick_GetTick()` 双模式：调度器启动后返回 FreeRTOS tick（长时间基准）；启动前/ISR 内用 `CYCCNT/(72MHz/1000)` 折算 ms（短时基准）—— **这是让 I2C/UART 超时检测在调度器启动前的自检阶段也能工作的关键设计**

#### 3.1.2 `i2c_hal.c` — 双总线 + 互斥锁 + 错误自愈

**目的**：抽象 STM32 硬件 I2C，提供两条独立总线（I2C1 给传感器、I2C2 给 OLED），屏蔽底层寄存器时序差异。

**核心设计**：
1. **双互斥锁**：`g_i2c_mutex`（I2C1）、`g_i2c2_mutex`（I2C2）。同总线多设备/多任务并发访问由锁串行化；两总线可并行。锁超时 100ms。
2. **统一事务函数 `i2c_xfer()`**：封装标准 I2C 时序 `START → 7bit地址+R/W → ADDR → 寄存器 → (读时重复START) → 数据 → STOP`。读单字节用 NACK+STOP，读多字节在最后一字节前 NACK+STOP（符合 I2C 协议）。
3. **主动错误检测**：`i2c_wait()` 等待 SR1 标志时，**同时检测 AF（从机不应答）/ BERR（总线错误）/ ARLO（仲裁丢失）**，一旦置位立即返回 -1，避免傻等满超时。
4. **总线自愈**：任何错误路径都执行 `i2c_bus_reset()`（`I2C_DeInit` + 重新 `I2C_Init` 100kHz），保证从总线死锁中自动恢复。

**每步超时 50ms**，足够覆盖最慢从机响应。

#### 3.1.3 `uart_hal.c` — 同步阻塞发送

**目的**：提供 UART1（蓝牙+调试）、UART2（语音）的初始化与发送。

**原理**：
- `uart_send()` 轮询 `TXE`（发送数据寄存器空）和 `TC`（发送完成）标志，200ms 超时保护
- ⚠️ **注意**：本文件只负责发送。UART **接收**分别在 `hc05.c`（UART1）和 `asr_pro.c`（UART2）中用轮询 `RXNE` 标志实现，未用中断/DMA
- GPIO 配置：TX 用 `AF_PP`，RX 用 `IPU`（UART1）或 `IN_FLOATING`（UART2，与 UART1 不一致）

#### 3.1.4 `keys.c` — 无阻塞消抖

**设计巧思**：利用 Display 任务 50ms 周期 > 机械抖动时长（<10ms）这一事实，**两次采样间毛刺无法表现为"持续按下"**，因此无需传统的 `vTaskDelay` 阻塞消抖。仅保留 300ms 防连按。PE4 前翻页、PE3 后翻页，内部上拉，按下为低。

### 3.2 传感器驱动层

#### 3.2.1 `max30102.c` — PPG 心率血氧传感器（I2C1, 0x57）

**初始化流程**（`MAX30102_Init`）：
1. **在线校验**：读 `PART_ID`(0xFF)，必须等于 `0x15`，否则返回 -1 不再配置 —— 优雅的接线/地址错误检测
2. 软件复位（MODE_CONFIG=0x40）→ 关中断 → 配 FIFO（滚动覆盖模式 0x10）→ 清 FIFO 指针 → 退出复位
3. 配 SpO2 模式：`SPO2_CONFIG=0x47`（ADC 量程 4096、采样率 100Hz、脉宽 411μs）、LED 电流 0x50（~16mA）、MODE=0x03（SpO2 双 LED 模式）

**数据读取**（`MAX30102_ReadData`）：
1. 读 FIFO 写指针(WR)和读指针(RD)，`(WR-RD) & 0x1F` 算可用样本数（5-bit 深度，滚动 32）
2. 一次性 burst 读全部样本（每样本 6 字节：Red[18:0] + IR[18:0]），ADC 值掩码 `0x3FFFF`
3. 解码到本地 `ir_dec[32]`/`red_dec[32]`，**直接调用 `PPG_ProcessSamples()`** 送入算法层
4. 调用方可传 NULL 跳过原始数据拷贝 —— main.c 正是传 NULL，避免在 2KB 的 Sensors 栈上再分配大缓冲

#### 3.2.2 `mpu6050.c` — 六轴加速度 + 芯片温度（I2C1, 0x68）

- 唤醒（PWR_MGMT_1=0 退出睡眠）、设 ±2g 量程（ACCEL_CONFIG=0，灵敏度 16384 LSB/g）
- `MPU6050_ReadData`：从 `ACCEL_XOUT_H`(0x3B) **一次 burst 读 8 字节**（X/Y/Z 加速度 6 字节 + 温度 2 字节），减少 I2C 往返
- 温度公式：`36.53 + raw/340`（datasheet 标准），读取失败回退 25°C（`MPU6050_TEMP_FALLBACK`），用作体温补偿的环境参考

#### 3.2.3 `ds18b20.c` — 1-Wire 数字温度（PA0）

**软件模拟 1-Wire 时序**（全部用 `taskENTER_CRITICAL()` 包裹，禁抢占保证时序）：
- `ow_reset()`：拉低 500μs → 释放 → 等 60μs 读 presence（从机拉低表示在线）→ 等 420μs 恢复
- `ow_write_bit/read_bit`：标准 1-Wire 位时序（写 1：拉低 5μs 释放 65μs；写 0：拉低 65μs 释放 5μs）
- `ow_crc8()`：Dallas/Maxim 反向多项式 0x8C 的 CRC-8，校验 scratchpad 全 9 字节

**三步温度读取流程**：
1. `DS18B20_StartConversion()`：发 Skip ROM(0xCC) + Convert T(0x44)，启动转换（约 750ms）
2. 等待 ≥750ms（main.c 用 4×200ms 周期保证）
3. `DS18B20_ReadData()`：发 Skip ROM + Read Scratchpad(0xBE)，读 9 字节，CRC 校验后 `raw/16.0` 得温度
- CRC 失败返回 -1（main.c 显示 "--.- C"），总线无响应返回 -2

#### 3.2.4 `ds1302.c` — 三线 RTC（PB1=CLK, PB12=DAT, PB9=CE）

**软件模拟三线时序**（CE + DAT + CLK，类 SPI）。

**亮点设计**：
1. **晶振停振自启动**（`DS1302_Init`）：读秒寄存器，若 `CH` 位（bit7）=1 表示振荡器停振（换电池后常态），则清除 CH 位启动振荡，**保留用户已设的秒值** —— 解决 DS1302 出厂/换电池后时间不走的经典问题
2. **三段自检**（`DS1302_SelfTest`）：
   - 通信测试：读秒 ≠ 0xFF
   - RAM 读写测试：写 0xA5 模式到 RAM(0xC0) 再回读
   - 写保护验证：开 WP 后写 0xFF 验证被拒绝
3. 读写用 burst 模式（0xBF/0xBE），BCD↔DEC 转换，写操作全程关写保护(0x8E 0x00)→写→开保护(0x8E 0x80)

### 3.3 算法层（项目核心）

`algorithms.c` 是整个项目的智慧所在，集成了 PPG 心率、SpO2 血氧、计步、运动识别、体温补偿五个子系统。

#### 3.3.1 PPG 心率算法

**信号处理链**：
```
100Hz采样 → 256点环形缓冲 → 取最近200点窗口 → 高通+低通带通滤波
         → 动态阈值 → 局部极大值峰值检测 → 峰间隔均值 → EMA平滑 → 心率
```

**关键技术点**：

1. **环形缓冲 + 绝对索引**：`ppg_ir[256]`/`ppg_red[256]` 环形存储，`ppg_total` 记录累计样本数（永不回绕），用于生成峰值的**绝对索引**，避免环形缓冲导致峰检测错乱

2. **一阶 RC 带通滤波器**（跨调用保留状态 `lp_state/hp_state/x_prev`，保证连续性）：
   - 高通（截止 0.5Hz，去基线漂移/呼吸干扰）：`yhp = α_hp·(prev_hp + x − prev_x)`
   - 低通（截止 5Hz，去高频噪声）：`ylp = prev_lp + α_lp·(yhp − prev_lp)`
   - α 由 `dt/(RC+dt)` 离散化，RC=1/(2π·fc)

3. **动态阈值峰值检测**：阈值 = `mean + 0.8×std`（自适应信号强度），要求候选点是局部极大值（>左右邻居），且距上一峰 ≥0.4s

4. **心率计算**：取最近 8 个峰间隔求平均周期，`HR = 60/avg_period`，限幅 30~200bpm

5. **EMA 平滑 + 无信号判定**：α=0.15 指数移动平均防跳变；信号 `std < 0.2` 判定手指离开，清零心率

#### 3.3.2 SpO2 血氧算法

- **R 值**：`R = (std_red/mean_red) / (std_ir/mean_ir)`，即红光与红外光 AC/DC 比值之比
- **公式**：`SpO2 = A − B×R`，默认 A=110, B=25
- **在线校准**：`Set_Spo2_Calibration(A,B)` 可通过蓝牙 `CAL` 命令实时调整（用标准血氧仪对比标定）
- 限幅 [50, 100]，EMA 0.15 平滑

#### 3.3.3 计步算法（`Step_ProcessAccel`）

**核心思想**：去除重力分量后，检测净加速度的超阈值峰值。

1. **重力分离**：`grav = 0.98×grav + 0.02×mag`（高比例 EMA 缓慢跟踪重力，因重力是低频直流分量）
2. **净加速度**：`acc = mag − grav`（去除重力，只留运动分量）
3. **自适应阈值**：`thr = 0.995×thr + 0.005×|acc|`（跟随活动强度变化——静止时阈值低，剧烈运动时阈值高）
4. **启动稳定**：前 10 次（~2s）静默期不计数，让 grav/thr 收敛（`STEP_SETTLE_COUNT`）
5. **步检测**：`acc > thr` 且距上一步 ≥400ms（防同一动作重复计数）
6. **步计数**：全局 `steps`，自增用临界区保护（因 ASR 任务会跨任务清零）

#### 3.3.4 运动状态识别

基于步频和晃动能量分类：
- 取最近 ≥3 步间隔求平均步频 `spm = 60000/avg_interval`
- `WALKING`：spm 40~120；`RUNNING`：spm>120
- 无步且空闲>2s：`SHAKING`（晃动能量>400）或 `UNKNOWN`（静止）
- 晃动能量：`0.9×旧 + 0.1×|acc|` 衰减累积

#### 3.3.5 体温补偿（`Compensate_Temperature`）

**原理**：DS18B20 测的是皮肤温度，需补偿到核心体温。皮肤与核心的温差随环境温度变化：
```
delta = 环境温度(MPU6050板温) − 25°C参考
offset = 2.5 − 0.05×delta   （限幅 [1.0, 3.5]°C）
体温 = 皮肤温度 + offset
```
环境越热 → offset 越小（皮肤与核心温差缩小）；环境越冷 → offset 越大。

### 3.4 外设交互层

#### 3.4.1 `oled_ssd1306.c` — OLED 显示（I2C2, 0x3C）

- **帧缓冲**：`framebuf[8][128]`（8 页 × 128 列 = 1KB）+ `dirty[8]` 脏页标记
- **脏页刷新**（`OLED_Flush`）：只重写 dirty=1 的页，**大幅降低 I2C2 带宽占用**（满屏 1KB，单页 128B）
- 字模 `font5x7.h`：ASCII 32~126 共 95 字符，每字 5 字节列 + 1 字节间隔 = 6px 宽
- 5 个显示函数：`ShowHeartRate/SpO2/Steps/MainPage` + main.c 内联绘制 Temp/Time 页面

#### 3.4.2 `hc05.c` — 蓝牙通信（UART1）

**波特率自动探测**（`HC05_Init`）：HC-05 出厂或被改过波特率时，先试目标波特率发 `AT`，失败则遍历 {38400, 115200, 57600, 19200}，命中后用 `AT+UART=baud,0,0` 改回目标波特率 —— **应对不确定的模块配置**。

**主循环 `HC05_Process`**：
1. **清 ORE 标志**（STM32F1xx UART 经典坑：Overrun Error 会锁死接收，必须读 DR 清除）
2. **行缓冲命令解析**：以 `\r\n` 分隔，解析 `CAL A B`（SpO2 校准）和 `TIME HH:MM:SS DD/MM/YY`（设时钟）
3. **2 秒定时上报**：`{"hr":N,"spo2":N,"steps":N,"temp":N.NN}` JSON

#### 3.4.3 `asr_pro.c` — 语音识别（UART2）

- 单字节命令码 `switch` 分发（0x01~0x09）
- 大部分命令直接调用 OLED 显示函数
- `ASR_CMD_NEXT`(0x08) 置 `g_page_advance` 标志，由 Display 任务翻页（**正确的跨任务通信方式**）
- `ASR_CMD_STEPRST`(0x03) 调 `Reset_StepCount()`（内部用临界区，安全）

### 3.5 应用层（main.c / 任务调度）

#### 3.5.1 初始化流程（9 步）

```
1. SystemInit + SystemCoreClockUpdate + Systick_Init   (内核/时钟/DWT)
2. PB8 蜂鸣器输出低静音                                  (避免开机噪音)
3. I2C_HAL_Init + I2C2_Init + UART1_Init(115200)        (总线)
4. PPG_Init                                             (算法层滤波器系数)
5. MAX30102/MPU6050/DS18B20/DS1302_Init                 (传感器)
6. OLED/Keys/HC05_Init(9600)/ASR_Init(9600)             (外设)
7. DS1302_SelfTest + UART 输出结果                       (自检报告)
8. 读 RTC 时间输出                                       (验证)
9. 创建 4 任务 + vTaskStartScheduler                    (启动调度)
```

#### 3.5.2 栈溢出钩子

`vApplicationStackOverflowHook`：检测到栈溢出时，重初始化 UART1(115200) 并输出 `STACK OVERFLOW: <任务名>`，然后死循环。配合 `configCHECK_FOR_STACK_OVERFLOW=1` 使用。

#### 3.5.3 Sensors 任务的 DS18B20 时序处理

```c
if (ds18b20_tick == 0)      DS18B20_StartConversion();   // 第0周期启动
else if (ds18b20_tick >= 4) DS18B20_ReadData(...);        // 第4周期读取(≥800ms)
```
用 4 个 200ms 周期（800ms）覆盖 DS18B20 的 750ms 转换时间，读完后 `continue` 立即开始下一轮（不等当次 vTaskDelay）。

## 四、关键实现原理深入

### 4.1 为什么 PPG 滤波器状态要跨调用保留？

`PPG_ProcessSamples` 每次只处理新到的若干样本（≤32），但带通滤波器是**有状态的递归滤波器**（输出依赖历史输入输出）。若每次都从零初始化滤波器，窗口边界会产生严重失真。因此 `lp_state/hp_state/x_prev` 作为文件级 static 变量跨调用保留，相当于把滤波器当成一个连续运行的流处理器——这是正确的工程做法。

### 4.2 为什么体温读取要用临界区？

`g_temperature` 是 `float`（4 字节）。在 Cortex-M3 上，**float 读写不是单条指令原子操作**（STR/LDR 是 32 位原子，但编译器可能用多条指令访问 float，且 `valid` 与 `temperature` 是两个独立变量）。若 Sensors 任务在 Display 读取 temperature 的两条指令之间更新了 valid 标志，会出现「valid=新值 但 temperature=旧值」的不一致快照，或 float 本身的字节撕裂。`taskENTER_CRITICAL()` 取快照解决此问题（main.c:132-135）。

### 4.3 I2C 错误自愈的价值

STM32F1xx 的硬件 I2C 以"设计有 bug"著称（ST 官方 errata 列出多个问题），典型表现是总线偶尔卡死（某从机拉低 SDA 不释放）。本工程的 `i2c_bus_reset()`（DeInit+ReInit）能有效从这类软故障恢复，避免手环运行中突然所有传感器失灵——这是**生产级健壮性**的体现。

### 4.4 MAX30102 FIFO 读取与算法解耦

驱动层解码后**直接调用算法层** `PPG_ProcessSamples()`，而不是返回原始数据让 main.c 处理。这样：
- main.c 无需在 2KB 的任务栈上分配 1KB 缓冲
- 算法层用文件级 static 缓冲，生命周期跨越任务调用
- 关注点分离：main.c 只调度，不碰信号处理

## 五、代码评审

> 按 code-reviewer 规范，分 Critical / Improvements / Nitpicks 三层。
> 整体评价：**这是一个工程质量相当高的嵌入式学生/毕设级项目**，分层清晰、注释详尽、错误处理周到，有若干生产级设计（I2C 自愈、CRC 校验、波特率探测）。以下问题均非阻断性。

### 5.1 Critical（需关注，影响正确性或健壮性）

| # | 位置 | 问题 | 说明 |
|---|------|------|------|
| C1 | `asr_pro.c` ↔ `oled_ssd1306.c` | **Voice 任务与 Display 任务无锁共享 OLED framebuffer** | Voice 任务（0x01~0x07,0x09 命令）直接调 `OLED_Show*`/`OLED_DrawString` 写 framebuffer，与 Display 任务的周期刷新并发。两者都调 `OLED_Flush()`，可能产生脏页标记错乱或半截画面。实际因语音命令稀发+dirty 粒度，冲突概率低，但理论上不严谨。建议：Voice 任务只置标志位（如 `g_voice_page`），由 Display 任务统一渲染。 |
| C2 | `main.c:237,251` + `vApplicationStackOverflowHook` | **UART1 波特率被 HC05 改写后，调试输出会乱码** | `main` 先 `UART1_Init(115200)` 输出自检，后 `HC05_Init(9600)` 会把 UART1 改为 9600。栈溢出钩子又用 115200 输出——此时 HC05 在线会收到乱码。建议：统一调试波特率，或栈溢出钩子内不重初始化 UART（可能破坏 HC05 状态）。 |
| C3 | `algorithms.c: compute_hr` 峰值去重 | **窗口滑动可能重复检测同一峰** | 每次处理新样本都重新扫描整个 200 点窗口找峰，依赖"新峰 abs_idx > 上次峰 + min_dist"去重。若 min_dist(40样本) < 窗口内同峰位置，同一峰的局部极大可能在多次调用中被重复尝试（虽有 min_dist 挡，但逻辑依赖 abs_idx 单调递增，环形缓冲回绕时需验证）。建议：峰值检测只扫描**本次新增样本区间**而非全窗口。 |

### 5.2 Improvements（建议改进，提升质量）

| # | 位置 | 建议 |
|---|------|------|
| I1 | `uart_hal.c:64` | UART2 RX 引脚 PA3 用 `IN_FLOATING`，而 UART1 的 PA10 用 `IPU`。建议统一用 `IPU`（悬空时为确定高电平，更稳定），尤其 ASR 模块未连接时避免浮空噪声。 |
| I2 | `mpu6050_config.h: STEP_MIN_INTERVAL_MS=400` vs `README.md`（写 250ms/240步每分） | **配置与文档不一致**。代码实际是 400ms（150步/分上限）。需确认哪个是设计意图并统一。 |
| I3 | `hc05.c` / `asr_pro.c` | UART 接收用**轮询 RXNE**，命令处理期间会阻塞任务。建议改用中断+环形缓冲（或 DMA），释放 CPU 并降低命令丢失风险。当前 20ms/100ms 轮询周期在高速蓝牙数据流下可能丢字节。 |
| I4 | `main.c` 体温/时间页面 vs `asr_pro.c` | **DRY 违规**：体温、时间页面的 OLED 绘制逻辑在 main.c（Display 任务）和 asr_pro.c（Voice 任务）中重复实现。建议抽取为 `OLED_ShowBodyTemp()` / `OLED_ShowTime()` 公共函数。 |
| I5 | `hc05.c: rxbuf/txbuf` 各 128B static | 行缓冲无溢出回绕处理，超长命令静默截断。建议加长度告警或环形缓冲。`TIME` 命令 sscanf 成功阈值是 `>=5`（缺年份时仍写入未初始化的 y），应改为 `==6`。 |
| I6 | `keys.c` | `key_read` 用函数内 `static uint32_t t` 保存 last_tick，导致函数不可重入。当前单任务调用无碍，但若未来多任务复用会出错。建议改由调用方传入状态指针。 |
| I7 | `algorithms.c` | `hr`/`spo2`/`steps` 是 `static volatile int`，getter 无临界区。M3 上 32 位读原子可接受，但 `steps` 被跨任务清零（Reset）和自增，建议读取也加临界区以保证读到一致快照（虽实际影响小）。 |
| I8 | `oled_ssd1306.c: OLED_DrawString` | x 坐标累加 6 不检查越界（>128 会写越界 framebuffer）。当前调用方都控制了长度，但防御性编程应加检查。 |

### 5.4 优秀设计点（值得肯定）

1. **I2C 错误自动总线复位**（`i2c_bus_reset`）—— 生产级健壮性
2. **MAX30102 PART_ID 在线校验** —— 接线错误早发现
3. **DS1302 晶振停振(CH位)自启动 + 三段自检** —— 解决换电池痛点
4. **DS18B20 CRC-8 校验** —— 数据完整性保障
5. **HC-05 波特率自动探测** —— 应对不确定的模块配置
6. **PPG 滤波器状态跨调用保留** —— 信号处理正确性
7. **OLED 脏页刷新** —— 降低 I2C 带宽
8. **体温读取 float 撕裂防护**（临界区快照）—— 多任务数据一致性
9. **DWT 周期计数器精确定时** —— 替代 SysTick 满足 1-Wire 时序
10. **配置参数全部集中在 `*_config.h`** —— 可维护性好，调参无需改算法
