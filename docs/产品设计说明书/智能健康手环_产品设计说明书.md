## 第1章 概述

### 1.1 产品定位

智能健康手环是一款基于 STM32F103ZE 微控制器的可穿戴健康监测设备。它集成多种传感器，实时采集心率、血氧饱和度（SpO₂）、体温、步数和实时时钟数据，通过 OLED 屏幕本地显示，同时支持蓝牙无线传输至手机端进行数据接收。

### 1.2 功能清单

| 序号 | 功能模块 | 功能描述 | 实现方式 |
|------|---------|---------|---------|
| 1 | 心率检测 | 实时测量脉搏心率（BPM） | MAX30102 PPG 传感器 + 自适应阈值峰值检测算法 |
| 2 | 血氧检测 | 实时测量血氧饱和度（%） | MAX30102 双波长光学测量 + R-ratio 校准公式 |
| 3 | 步数计数 | 自动累计行走步数 | MPU6050 加速度计 + 重力分离 + 自适应阈值计步算法 |
| 4 | 运动状态识别 | 区分走路/跑步/晃动/静止 | 基于步频和晃动能量的四态分类器 |
| 5 | 体温检测 | 皮肤温度测量并补偿为核心体温 | DS18B20 数字温度传感器 + 环境温度补偿算法 |
| 6 | 实时时钟 | 显示当前日期时间 | DS1302 RTC 模块（带纽扣电池掉电保持） |
| 7 | OLED 显示 | 5 页轮转显示各项数据 | SSD1306 128×64 OLED + 帧缓冲 + 脏标记优化 |
| 8 | 蓝牙上报 | 每 2 秒自动推送 JSON 数据包 | HC-05 蓝牙串口透传模块 |
| 9 | 语音控制 | 语音命令切换页面/操作 | ASR PRO 离线语音识别模块 |
| 10 | 按键操作 | 两个按键实现翻页功能 | GPIO 输入 + 软件消抖 + 防连按 |

### 1.3 应用场景

- **日常健康监测**：用户佩戴手环，实时查看心率、血氧、体温等生理参数
- **运动辅助**：自动计步并识别运动状态（走路/跑步）
- **课程设计演示**：作为嵌入式系统课程的综合性设计项目，覆盖传感器驱动、信号处理算法、实时操作系统、无线通信等多个知识点

**总线分配策略**：MAX30102 和 MPU6050 共享 I2C1 总线（PB6/PB7），OLED 独占 I2C2 总线（PB10/PB11）。这样分配的理由是 MAX30102 以 100Hz 采样率持续读取 FIFO，若 OLED 同挂 I2C1 会造成带宽竞争，导致 PPG 数据丢失。

### 2.2 软件架构

采用四层分层架构，自顶向下为：

```
┌──────────────────────────────────────────────────────┐
│  应用层  (main.c, 4个FreeRTOS任务)                    │ ← "做什么"
│  vTaskSensors / vTaskDisplay / vTaskVoice / vTaskBT   │
├──────────────────────────────────────────────────────┤
│  算法层  (algorithms.c)                               │ ← "怎么算"
│  PPG信号处理 / 计步算法 / 体温补偿 / 运动状态分类      │
├──────────────────────────────────────────────────────┤
│  驱动层  (max30102.c, mpu6050.c, ds18b20.c,           │ ← "怎么读"
│           ds1302.c, oled_ssd1306.c, hc05.c, asr_pro.c)│
│  每个模块: Init() + ReadData() 统一接口                │
├──────────────────────────────────────────────────────┤
│  硬件抽象层  (i2c_hal.c, uart_hal.c)                   │ ← "怎么发"
│  封装 STM32 外设寄存器操作，含超时/复位/互斥锁         │
├──────────────────────────────────────────────────────┤
│  CMSIS / STM32F10x 标准外设库 / ARM Cortex-M3 硬件     │
└──────────────────────────────────────────────────────┘
```

**设计原则**：
- 每一层只调用下一层的接口，不跨层访问
- 驱动层各模块之间互不依赖（MAX30102 不知道 MPU6050 的存在）
- 算法层不接触任何硬件寄存器，仅处理 `float`/`int` 数据

### 2.3 FreeRTOS 任务划分

| 任务名 | 栈大小（字） | 优先级 | 执行周期 | 核心职责 |
|--------|-------------|--------|---------|---------|
| Sensors | 512 | 3（最高） | 200ms | 轮询 MAX30102/MPU6050/DS18B20，调用算法处理 |
| Display | 512 | 2 | 50ms | 按键消抖检测、页面轮转、OLED 脏标记刷新 |
| Voice | 384 | 2 | 100ms | 轮询 UART2 接收 ASR PRO 单字节命令并分发 |
| BT | 384 | 2 | 20ms | 轮询 UART1 收 AT/CAL/TIME 命令，每 2s 上报 JSON |

**优先级设计理由**：MAX30102 内部 FIFO 只有 32 个样本位，100Hz 采样率下约 320ms 就会溢出。Sensors 任务设为最高优先级 3，即使其他 3 个任务同时就绪也不会抢占它，保证 PPG 数据不丢失。

### 3.1 主控选型：STM32F103ZE

| 参数 | 规格 | 对本项目的意义 |
|------|------|--------------|
| 内核 | ARM Cortex-M3 @ 72MHz | 足够处理 100Hz PPG 信号的实时滤波和峰值检测 |
| Flash | 512KB | 本项目编译后约 35KB，余量极大 |
| SRAM | 64KB | FreeRTOS 堆 15KB + 全局任务栈 3.2KB + 全局缓冲 3KB，合计约 21KB，余量充足 |
| I2C | 2 路 | 恰好满足双总线架构（I2C1 传感器 + I2C2 OLED） |
| USART | 3 路 | USART1（蓝牙+调试）、USART2（语音），USART3 预留 |
| GPIO | 112 个（8×16-bit 端口 A~G） | 本项目使用 16 个，余量极大 |
| 工作电压 | 2.0V–3.6V | 与所有传感器模块电平兼容（3.3V） |
| 封装 | LQFP-144 | 引脚充裕，便于扩展 |

**选型理由**：STM32F103ZE 属于 STM32F1 系列高密度产品（HD系列），512KB Flash 和 64KB SRAM 为 FreeRTOS 多任务系统和大容量传感器数据缓冲提供了充裕空间。其外设资源与 C8T6 完全兼容，I2C/USART/GPIO 等外设覆盖本项目全部需求，且 LQFP-144 封装提供了更多 IO 扩展可能性。

### 3.3 I2C 双总线设计

| 总线 | SCL | SDA | 挂载设备 | 上拉电阻 | 说明 |
|------|-----|-----|---------|---------|------|
| I2C1 | PB6 | PB7 | MAX30102 + MPU6050 | 4.7kΩ × 2 | 共享总线，Mutex 保护，100kHz 时钟 |
| I2C2 | PB10 | PB11 | SSD1306 OLED | 4.7kΩ × 2 | 独占总线，无竞争，100kHz 时钟 |

**双总线理由**：

MAX30102 以 100Hz 采样率运行，每次读取最多 192 字节。若 OLED 也挂在 I2C1，每 500ms 刷新 1KB 帧缓冲会占用约 80ms 总线时间，导致 PPG FIFO 读取延迟超过 320ms 溢出窗口。将 OLED 独立到 I2C2 彻底消除这一问题。

## 第4章 软件设计说明

### 4.1 启动流程

系统上电后 `main()` 函数按以下顺序初始化：

```
步骤1: SystemInit() + Systick_Init()      ← 内核时钟 72MHz, SysTick 1ms
步骤2: I2C_HAL_Init() + I2C2_Init()       ← 两条 I2C 总线, 创建互斥锁
        UART1_Init(115200)                 ← 调试串口（后续 HC-05 重配为 9600）
步骤3: PPG_Init()                          ← 计算滤波系数 α_lp, α_hp
步骤4: MAX30102_Init() / MPU6050_Init()    ← 传感器寄存器配置
        DS18B20_Init() / DS1302_Init()
步骤5: OLED_Init() / Keys_Init()           ← 外设初始化
        HC05_Init(9600) / ASR_Init(9600)
步骤6: DS1302_SelfTest()                   ← RTC 自检（通信 + RAM + WP）
步骤7: DS1302_ReadTime()                   ← 读取并打印当前时间（验证用）
步骤8: xTaskCreate() × 4                   ← 创建 FreeRTOS 任务
步骤9: vTaskStartScheduler()               ← 启动调度器, 永不返回
```

**设计要点**：
- PPG_Init() 在传感器 Init 之前调用，确保 MAX30102 产出第一个样本时滤波器已就绪
- 调试串口初始为 115200 bps，HC05_Init() 内部会尝试 9600→38400→115200→57600→19200 自动探测蓝牙波特率
- DS1302 自检在 OLED 显示之前执行，自检结果通过串口输出，不依赖屏幕

### 4.2 vTaskSensors — 传感器采集任务（200ms, 优先级3）

**设计思路**：所有传感器在同一个任务中顺序读取，避免跨任务共享 I2C 总线的复杂性。DS18B20 因 750ms 转换时间限制，采用分频计数实现 800ms 读取周期。

```c
static void vTaskSensors(void *pvParameters)
{
    static uint8_t ds18b20_tick = 0;

    for (;;) {
        /* ① MAX30102: 读取 FIFO → 内部自动调用 PPG_ProcessSamples() */
        {
            int32_t  ir_buf[MAX30102_BUF_LEN];     // 栈上分配, 128 元素
            int32_t  red_buf[MAX30102_BUF_LEN];
            uint16_t count = MAX30102_BUF_LEN;
            MAX30102_ReadData(ir_buf, red_buf, &count);
            // ReadData 内部: 读FIFO指针 → 批量读原始数据 → 18-bit解码
            //              → 输出到调用方缓冲区 → PPG_ProcessSamples()
        }

        /* ② MPU6050: 一次 I2C 读 8 字节 (加速度6 + 温度2) */
        int16_t ax = 0, ay = 0, az = 0;
        float   chip_temp = MPU6050_TEMP_FALLBACK;  // 默认 25°C (I2C 失败时)
        if (MPU6050_ReadData(&ax, &ay, &az, &chip_temp) == 0) {
            Step_ProcessAccel(ax, ay, az);
        }

        /* ③ DS18B20: 两步异步操作 (转换 → 等待 3 周期 → 读取) */
        if (ds18b20_tick == 0) {
            DS18B20_StartConversion();      // 发送 0xCC 0x44, 启动 750ms 转换
        } else if (ds18b20_tick >= 4) {      // 4×200ms = 800ms ≥ 750ms
            float skin_temp;
            if (DS18B20_ReadData(&skin_temp) == 0) {
                g_temperature = Compensate_Temperature(skin_temp, chip_temp);
                g_temp_valid  = 1;          // 标记数据有效, 供 Display/BT 读取
            }
            ds18b20_tick = 0;
            continue;   // 跳过 vTaskDelay, 立即开始下一轮转换
        }
        ds18b20_tick++;

        vTaskDelay(pdMS_TO_TICKS(200));     // 阻塞 200ms, 让出 CPU
    }
}
```

**MAX30102 缓冲区在栈上分配**：每个周期进入 `{}` 块时在栈上创建 128×2×4 = 1024 字节缓冲区，离开块时自动回收。这样做避免了全局静态缓冲区的并发访问问题。

**DS18B20 异步转换模式**：vTaskDelay(200ms) 本身提供了自然的时间间隔。`ds18b20_tick` 从 0 计数到 4（4×200ms = 800ms），超过 DS18B20 12-bit 转换所需的 750ms，保证读取时数据已就绪。

### 4.3 PPG 信号处理管线（algorithms.c 核心算法）

这是整个项目计算密集度最高的模块。原始 PPG 信号经过五级处理得到心率和血氧值：

```
MAX30102 FIFO (IR+Red raw)
        │
        ▼
┌─────────────┐
│ ① 带通滤波   │  高通 0.5Hz (去直流) + 低通 5Hz (去毛刺)
│   一阶 IIR   │  y_hp[n] = α_hp × (y_hp[n-1] + x[n] - x[n-1])
│              │  y_lp[n] = y_lp[n-1] + α_lp × (y_hp[n] - y_lp[n-1])
└──────┬──────┘
       │ 滤波后波形
       ▼
┌─────────────┐
│ ② 动态阈值  │  threshold = mean + 0.8 × stddev
│   峰值检测   │  满足 filtered[i] > threshold 且为局部最大值 → 峰值
└──────┬──────┘
       │ 峰值时间序列
       ▼
┌─────────────┐
│ ③ 心率计算  │  avg_period = mean(峰间间隔) / 100Hz
│              │  HR = 60 / avg_period → 合理性检查(0.3-2.0s)
└──────┬──────┘
       │ 原始心率 (波动大)
       ▼
┌─────────────┐
│ ④ EMA 平滑  │  ema_hr = 0.15 × new_hr + 0.85 × ema_hr
│   α = 0.15  │  数字不会剧烈跳动, 每次只接受 15% 新信息
└──────┬──────┘
       │ 最终心率 BPM
       ▼
┌─────────────┐
│ ⑤ SpO₂ 计算 │  R = (AC_red/DC_red) / (AC_ir/DC_ir)
│              │  SpO₂ = 110 - 25 × R → [50, 100] 裁剪
└─────────────┘
       │
       最终: 心率(int) + 血氧(int)
```

#### 4.3.1 IIR 滤波系数计算

```c
void PPG_Init(void)
{
    float rc_lp = 1.0f / (2.0f × 3.1415926535f × 5.0f);  // LP 时间常数 (5Hz)
    float rc_hp = 1.0f / (2.0f × 3.1415926535f × 0.5f);  // HP 时间常数 (0.5Hz)
    float dt    = 1.0f / 100.0f;                          // 采样间隔 (100Hz)
    alpha_lp = dt / (rc_lp + dt);   // 低通平滑系数
    alpha_hp = dt / (rc_hp + dt);   // 高通平滑系数
}
```

**设计要点**：滤波系数在 Init 中预计算，避免每个样本重复计算 `1/(2πfc)`，节省 CPU 时间。截止频率 0.5Hz（HP）和 5Hz（LP）构成带通滤波器，恰好覆盖正常人静息心率范围（30–200 BPM = 0.5–3.3Hz）。

#### 4.3.2 动态阈值峰值检测

```c
float mean = calc_mean(filtered, N);          // 窗口均值
float stdv = calc_std(filtered, N, mean);     // 窗口标准差（反映信号幅度）
float thresh = mean + 0.8f × stdv;           // 动态阈值

for (uint16_t i = 1; i < N - 1; i++) {
    if (filtered[i] > thresh &&               // ① 高于阈值
        filtered[i] > filtered[i - 1] &&      // ② 比左边高 (上升沿)
        filtered[i] > filtered[i + 1]) {      // ③ 比右边高 (下降沿) → 局部峰值

        uint32_t abs_idx = ppg_total - N + i;          // 转换为全局索引
        uint32_t min_dist = (uint32_t)(0.4f × 100.0f); // 最小峰间距 = 40 样本
        if (peak_count == 0 ||
            abs_idx > peak_times[(peak_count - 1) % MAX_PEAKS] + min_dist) {
            add_peak(abs_idx);  // 记录峰值时刻, 最多保留 32 个
        }
    }
}
```

**为什么用 `mean + 0.8 × std` 而非固定值**：不同人的手指厚度、肤色、按压力度导致 PPG 信号幅度差异可达 5 倍。动态阈值自动适应每个人的信号特征，无需手动校准。

**最小峰间距 40 样本（400ms）**：对应 150 BPM 上限，有效过滤 PPG 波形的重搏切迹（dicrotic notch）造成的假峰。

#### 4.3.3 EMA 平滑（α = 0.15）

```c
// 每个 PPG 处理周期结束时
if (new_hr > 0) {
    if (ema_hr == 0.0f) ema_hr = (float)new_hr;  // 首次直接赋值，避免从 0 爬升
    ema_hr = 0.15f × (float)new_hr + 0.85f × ema_hr;
    hr = (int)(ema_hr + 0.5f);  // 四舍五入
}
```

**α = 0.15 的含义**：每次更新只接受 15% 的新测量值、保留 85% 的历史值。假设真实心率从 70 突变为 80：第 1 次 → 71.5，第 2 次 → 72.8，第 5 次 → 77.4，约 10 次（2 秒）后稳定在 80 附近。变化平滑不跳跃，同时能跟上真实变化。

### 4.4 计步算法（Step_ProcessAccel）

#### 4.4.1 重力分离

```c
float mag = sqrtf((float)ax×ax + (float)ay×ay + (float)az×az); // 加速度幅值

if (grav == 0.0f) grav = mag;                           // 首次初始化
grav = 0.98f × grav + 0.02f × mag;                      // 重力缓慢追踪
float acc = mag - grav;                                  // 运动加速度 = 总幅值 − 重力
```

**重力 EMA 系数 0.98**：每次只更新 2%，重力估计像一个"迟钝的朋友"，不会被短暂的甩手动作迷惑，但能跟上姿态的缓慢变化（如手臂从垂放到抬起）。

#### 4.4.2 自适应阈值 + 步态检测

```c
thr = 0.995f × thr + 0.005f × fabsf(acc);   // 阈值缓慢自适应

if (acc > thr && (now - last_step) > 400) {  // 超阈值 + 距上步 ≥ 400ms
    steps++;                                  // 计一步
    last_step = now;
}
```

**最小间隔 400ms** = 最大步频 150 步/分钟，有效过滤抖动和伪步。

#### 4.4.3 运动状态分类

| 状态 | 判定条件 | 阈值 |
|------|---------|------|
| RUNNING | 有近期步数 且 步频 > 120 步/分钟 | 步/分钟 |
| WALKING | 有近期步数 且 步频 40–120 步/分钟 | 步/分钟 |
| SHAKING | 无步数 > 2 秒 且 晃动能量 > 400 | 能量单位 |
| UNKNOWN | 无步数 且 晃动能量小 | — |

### 4.5 体温补偿算法

```c
float Compensate_Temperature(float raw_temp, float ambient_temp)
{
    float delta = ambient_temp - 25.0f;                   // 环境温差（相对 25°C）
    float offset = 2.5f - 0.05f × delta;                  // 补偿量公式

    if (offset < 1.0f) offset = 1.0f;                     // 最少补 1°C
    if (offset > 3.5f) offset = 3.5f;                     // 最多补 3.5°C

    return raw_temp + offset;
}
```

**补偿公式**：`核心体温 = 皮肤温度 + (2.5 − 0.05 × (环境温度 − 25))`

环境温度参考来自 MPU6050 芯片内部温度传感器（读取加速度数据时顺带读取，不增加 I2C 事务）。

### 4.6 I2C 硬件抽象层设计

`i2c_hal.c` 是整个驱动层的基础。核心是一个通用事务函数 `i2c_xfer()`，处理完整的 I2C 读写序列：

```
i2c_xfer(I2Cx, mutex, dev_addr, reg, data, len, is_read):
  ① i2c_lock(mutex)          ← 拿互斥锁, 最多等 100ms
  ② START → Send 7-bit addr  ← 发送设备地址 (写方向)
  ③ Send reg address         ← 发送寄存器地址
  ④ if read:
        Repeated START        ← 重复起始条件
        Send addr (read)      ← 发送设备地址 (读方向)
        Read len bytes        ← 连续读 len 个字节
     else:
        Write len bytes       ← 连续写 len 个字节
  ⑤ STOP
  ⑥ 如果失败: I2C_GenerateSTOP + i2c_bus_reset (DeInit→ReInit)
  ⑦ i2c_unlock(mutex)
```

**关键设计特性**：

| 特性 | 实现 | 作用 |
|------|------|------|
| 互斥锁保护 | `xSemaphoreTake(mtx, 100ms)` | 防止 I2C1 上 MAX30102 和 MPU6050 并发访问 |
| 超时机制 | 每个状态等待最多 50ms | 防止从设备死机导致永久阻塞 |
| 总线复位 | `I2C_DeInit → I2C_Init` | 通信失败后自恢复，防止 SDA 线被拉死 |
| 函数统一 | 4 个公开函数都是 `i2c_xfer` 的薄封装 | 消除重复代码，修改一处影响全部 |

### 4.7 HC-05 蓝牙协议

#### 4.7.1 自动波特率探测

```c
void HC05_Init(uint32_t baud)
{
    if (hc05_try_baud(baud) == 0) return;  // 尝试用户指定波特率

    // 失败则遍历常见波特率: 38400 → 115200 → 57600 → 19200
    static const uint32_t fallbacks[] = {38400, 115200, 57600, 19200};
    for (int i = 0; i < 4; i++) {
        if (hc05_try_baud(fallbacks[i]) == 0) {
            // 发送 AT+UART 命令将模块永久设为用户指定波特率
            snprintf(cmd, sizeof(cmd), "AT+UART=%lu,0,0\r\n", baud);
            UART1_Send(cmd, strlen(cmd));
            Delay_ms(200);
            UART1_Init(baud);  // 重配本地 UART 为新波特率
            return;
        }
    }
    UART1_Init(baud);  // 全部失败, 硬上
}
```

**设计理由**：你不知道上一个使用者把 HC-05 设成了什么波特率。自动探测链保证在任何常见波特率下都能找到模块并重新配置。

ASR PRO 离线语音模块通过 UART2 发送单字节命令码。`ASR_ProcessUART()` 采用 switch-case 分发：

| 命令码 | 宏定义 | 功能 | 响应动作 |
|--------|--------|------|---------|
| 0x01 | ASR_CMD_HR | 查看心率 | OLED_ShowHeartRate(Get_HeartRate()) |
| 0x02 | ASR_CMD_STEPS | 查看步数 | OLED_ShowSteps(Get_StepCount()) |
| 0x03 | ASR_CMD_STEPRST | 归零步数 | Reset_StepCount() + 刷新显示 |
| 0x04 | ASR_CMD_SPO2 | 查看血氧 | OLED_ShowSpO2(Get_SpO2()) |
| 0x05 | ASR_CMD_TEMP | 查看体温 | 直接画体温页面 |
| 0x06 | ASR_CMD_TIME | 查看时间 | 直接画时间页面 |
| 0x07 | ASR_CMD_MAIN | 显示主页 | OLED_ShowMainPage() |
| 0x08 | ASR_CMD_NEXT | 下一页 | 设置 g_page_advance = 1 |
| 0x09 | ASR_CMD_ACTIVITY | 查看状态 | 显示运动状态 |

**任务间通信模式**：ASR 任务设置 `g_page_advance = 1`（volatile 全局变量），Display 任务在轮询时检测并清零。这是最简单的任务间信号传递方式，适合低频事件（翻页）。

### 4.9 OLED 显示优化

采用帧缓冲 + 脏标记双缓冲策略：

```c
static uint8_t framebuf[8][128];  // 8 页 × 128 列 = 1KB 显存镜像
static uint8_t dirty[8];          // 标记哪些页需要刷新

void OLED_Flush(void)
{
    for (uint8_t page = 0; page < 8; page++) {
        if (!dirty[page]) continue;     // ← 干净的页跳过, 节省 I2C 时间
        write_cmd(0xB0 + page);         // 选择页地址
        write_cmd(0x00); write_cmd(0x10); // 列地址 = 0
        write_data(framebuf[page], 128);  // 整页发送
        dirty[page] = 0;
    }
}
```

**优化效果**：最坏情况（全屏刷新）= 1024 字节 ≈ 80ms I2C 时间；典型情况（只改一行字）= 128 字节 ≈ 10ms。

## 第7章 可靠性与安全性设计

### 7.1 看门狗

FreeRTOS 未启用硬件独立看门狗（IWDG），但通过以下机制保证系统可靠性：

| 机制 | 实现 | 作用 |
|------|------|------|
| 栈溢出检测 | `configCHECK_FOR_STACK_OVERFLOW=1` | 任务栈溢出时触发 Hook 输出任务名并停机 |
| 任务看门狗 | 四个任务各自周期性执行 | 任一任务死循环不影响其他（抢占式调度） |
| IDLE 任务 | FreeRTOS 自动创建 | 所有任务阻塞时运行，不死机即证明调度器正常 |

**栈溢出 Hook 实现**：

```c
void vApplicationStackOverflowHook(TaskHandle_t xTask, char *pcTaskName)
{
    UART1_Init(115200);  // 重新初始化 UART1 到已知波特率
    UART1_Send("STACK OVERFLOW: ", 16);
    if (pcTaskName) UART1_Send(pcTaskName, strlen(pcTaskName));
    UART1_Send("\r\n", 2);
    for (;;) {}  // 停机，等待人工复位
}
```

### 7.2 I2C 总线异常恢复

每次 I2C 通信失败后，`i2c_xfer()` 执行以下恢复流程：

```
I2C_GenerateSTOP(I2Cx, ENABLE)  → 释放总线（防止 SDA 被从设备拉死）
i2c_bus_reset(I2Cx)             → DeInit + ReInit I2C 外设
i2c_unlock(mutex)               → 释放互斥锁（其他任务可继续使用总线）
return -1                       → 向上层报告错误
```

**为什么需要总线复位**：I2C 从设备（如 MAX30102）在静电干扰或电压波动时可能进入异常状态，将 SDA 线持续拉低。此时所有后续通信都失败。DeInit→ReInit 将 I2C 外设寄存器恢复为默认值，相当于"拔掉电源重插"。

### 7.3 DS18B20 CRC 校验

每次温度读取后对 9 字节 Scratchpad 进行 CRC-8 校验（多项式 0x8C）：

```c
if (ow_crc8(sp, 9) != 0)
    return -1;  // CRC 失败 → 丢弃数据，main.c 检查返回值
```

CRC 失败时 DS18B20_ReadData 返回 -1，调用方（vTaskSensors）不更新全局温度变量，Display 任务显示 "--.- C"。

### 7.4 1-Wire 时序保护

DS18B20 的 1-Wire 时序精度为微秒级（写 0 需拉低 60–120μs）。FreeRTOS 的任务切换恰好在此时可能打断时序。所有 1-Wire 操作都在临界区内执行：

```c
taskENTER_CRITICAL();       // 关闭任务切换和 SysTick 中断
ow_reset();
ow_write_byte(0xCC);
ow_write_byte(0x44);
taskEXIT_CRITICAL();        // 恢复
```

进入临界区的时间约 500μs × 3 = 1.5ms，对系统实时性影响可忽略不计。

### 7.5 UART Overrun Error 处理

USART 硬件在接收缓冲区未被及时读取时会设置 Overrun Error（ORE）标志并**停止接收**。蓝牙和语音任务在每次轮询开始时强制清除：

```c
if (USART_GetFlagStatus(USART1, USART_FLAG_ORE) != RESET) {
    (void)USART_ReceiveData(USART1);  // 读取 DR 寄存器清除 ORE 标志
}
```

### 7.6 信号无效保护

PPG 算法中当信号标准差 < 0.2（无手指或信号太弱）时：

```c
if (stdv < PPG_STD_ACTIVE_MIN) {  // 0.2
    hr = 0;       // 心率清零
    ema_hr = 0.0f; // EMA 历史清零（避免恢复后数据爬升缓慢）
    spo2 = 0;     // 血氧清零
    ema_spo2 = 0.0f;
}
```

这确保"没信号时不乱报数据"，而非持续输出上一个有效值误导用户。

### 7.7 ESD 与硬件保护

| 防护项 | 措施 |
|--------|------|
| I2C 总线 | SDA/SCL 各接 4.7kΩ 上拉电阻，限制电流 |
| 1-Wire 总线 | PA0 对 3.3V 接 4.7kΩ 上拉，防止浮空 |
